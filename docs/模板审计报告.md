## 一、总体评价

这是一个**下限很高、但"换皮守护"承诺存在系统性裂缝**的模板。

先说实测干净的部分（这些是审计中逐项核对过、确认无问题的）：

| 方面 | 实测结果 |
|---|---|
| canonical / hreflang / x-default | 全部 40 页输出正确，无 `/en` 前缀泄漏 |
| sitemap 覆盖 | 40 条 URL 与 out/ 的 40 个 HTML 页一一对应（含动态 slug 与 about/contact/privacy/faq） |
| JSON-LD | 全部可解析、`@context` 正确、URL 全绝对路径、日期合法 ISO |
| og:url / og 图 | og:url 与 canonical 逐页一致；og 图存在且实测 1200×630 |
| robots.txt | 静态导出下正常生成，内容与 robots.ts 一致 |
| title / description | 全站唯一、无缺失 |
| 质量门禁 | typecheck 干净、92 项测试通过、静态导出成功、内链零死链 |
| 工程文化 | 注释记录设计决策（如 alternates 浅合并陷阱、pagefind 语义）、promote 脚本带产物级兜底校验、prune-pagefind 删死 UI 包——这些是真实的好设计 |

但审计同样确认了五个**模式级**的系统性弱点，它们是下面几十条具体问题的共同根因：

1. **dev 与生产是两套宇宙**。"默认语言无前缀"这条 URL 规则只在构建期由 promote 脚本成立，`next dev` 下整个站是坏的（见 P0-1）。`npm start` 也是必崩的（P0-2）。模板的第一印象入口（clone → dev → 打开 localhost）全部踩坑。
2. **守护测试守护的是"配置清单"，不是"产物与约定"**。sitemap 真正的生成器零测试；llms.txt、404 页 POPULAR、Sidebar 动态 key、brandTokens 一致性全部零守护；多个测试断言硬编码了单语事实，加语言时红的是"过期断言"而非缺陷。
3. **豁免区里藏着脏东西**。check-swap 豁免 `data/`、`messages/`、`public/`、`scripts/`，于是上一任游戏的 `[how-to-fish content]` describe 名、llms.txt 里整套旧游戏事实、make-hero-avif 注释里的过期引用全部存活——"框架层零品牌残留"的承诺只在被扫描的目录内成立。
4. **同一件事有 2–5 份平行实现**：日期格式化 3 套（2 套时区不安全）、面包屑 3 种形态、hero 图片 3 条独立链路（webp / avif / jpg 各自硬编码）、数据访问 2 套范式（6 个死 accessor）。平行实现之间必然漂移，已经漂了。
5. **SOP 与代码漂移**：hero 链路描述与实现相反、NavItem `pack` 字段不存在、"四处同步删除"实际是六处、"sitemap 与内链校验自动跟随"实际不跟随。SOP 是这个模板的核心卖点文档，它的失真直接放大换皮风险。

## 二、P0：高优先级（建议立即修，合计约半天工作量）

### P0-1 dev 模式下整站不可用：根路径 404、全站内链 500/404

- **位置**：`app/layout.tsx:2`（过期注释）、`lib/site.ts:16`（localePath）
- **问题**：项目没有 `app/page.tsx` 也没有 middleware，`next dev` 的路由空间只有 `/en/*`。而 localePath 对默认语言输出无前缀路径（`/`、`/guides`…），全站导航/内链都基于它生成。实测：dev 下 `GET / → 404`，`GET /guides → 500`（404 fallback 错误页），仅 `/en` 可用；打开 `/en` 后点任何导航链接全部落 404/500。生产不受影响（promote 脚本构建期提升），但 **clone 后第一次 `npm run dev` 打开根地址就是 404，换皮者会以为模板坏了**。`app/layout.tsx:2` 注释还引用着已被删除的 `app/page.tsx`。
- **修复**：恢复一个 `app/page.tsx` 做 `redirect(defaultLocale)`（build 产物 out/index.html 会被 promote 脚本覆盖成真首页，互不冲突），同时修正过期注释。

### P0-2 `npm start` 必然崩溃

- **位置**：`package.json:8`
- **问题**：`"start": "next start"` 与 `output: 'export'` 不兼容，实测启动即崩（`routesManifest.dataRoutes is not iterable`，进程死亡）。仓库自带的 `scripts/serve-out.mjs`（支持 cleanUrls、MIME 对齐）没有挂到任何 npm script，也没有文档。
- **修复**：`"start": "node scripts/serve-out.mjs"`，并顺手加 `"preview"` 同款（见 P2）。

### P0-3 日期格式化三套实现，两套时区不安全：UTC 以西构建机上全站日期比数据早一天

- **位置**：`lib/date.ts:4`、`data/content-dates.ts:36`、`app/[locale]/(main)/guides/[slug]/page.tsx:19`（第三套，确定性）
- **问题**：date-only ISO（`'2026-09-18'`）被 `new Date()` 按 UTC 零点解析，`toLocaleDateString` 不传 timeZone 按构建机时区渲染。实测 `America/New_York` 下输出 `September 17, 2026`。影响 19 个 topic 页 + 2 个 monster + 2 个 boss 详情页，且与同页 JSON-LD 的 datePublished 相差一天。guides 详情页的私有实现（手动月名映射）恰恰规避了此问题，其注释还警告过这个坑——`content-dates.ts:35` 声称与它"保持一致"，实际相反。另 `regions/[slug]/page.tsx:189` 直接输出原始 ISO，第四种格式。
- **修复**：把 guides 页的确定性 humanDate 下沉为 `lib/date.ts` 唯一实现，全部消费方改调它。

### P0-4 TOC 是半接线的死功能：从未挂载 + xl 屏空占位 192px + 锚点全站缺失

- **位置**：`components/layout/toc.tsx:8`、`app/[locale]/(main)/layout.tsx:21`
- **问题**：`TableOfContents` 全仓库零引用；布局保留空 `<aside data-toc-root>`（xl 断点白占 192px + 24px gap，正文被压窄）。即使接线：组件用 `el.id || 'heading-'+i` 兜底，而全站 30 处 `<h2>` 无一携带 id，所有链接将指向不存在的锚点；effect 依赖 `[]`，客户端路由切换后不刷新。
- **修复**：要么删掉组件和空 aside；要么补全（h2 生成稳定 slug id + 挂载 + usePathname 依赖）。别留半成品。

### P0-5 浅色模式多处文本对比度低于 WCAG AA（实测 2.70–4.44:1）

- **位置**：`components/search/search-dialog.tsx:121`（/60→3.47）、`:129`（/50→2.68）、`components/search/search-trigger.tsx:12`（/60→3.41）、`components/layout/sidebar-nav.tsx:31`（/70→4.44）
- **问题**：`--color-foreground` (#2c3e50) 的透明度变体在白/popover/#fafafa 上全部低于 4.5:1，均为 12–14px 正文不适用大字豁免；暗色模式同位置全部通过（6.8–9.3）——**只有浅色是坏的**。
- **修复**：/50、/60 提到 /80 以上或直接换 `--color-muted-foreground`（#4e6373，对 #fafafa 为 5.99）。建议加一条读 globals.css 计算主要组合对比度的守护测试，让换皮改主题色时自动拦截。

### P0-6 /monsters 头图缺 width/height，首屏 CLS 下推约 330px

- **位置**：`app/[locale]/(main)/monsters/page.tsx:36`（game/page.tsx:32 同）
- **问题**：`<img class="w-full object-cover">` 无尺寸属性也无 aspect-ratio 容器；图实际 1200×400，在 992px 容器里加载完成后高度从 0 跳到 ~330px，把筛选表和正文整体下推（图上方仅 ~180px 内容，确在首屏，lazy 不救 CLS）。对照 hero.tsx 有 `aspect-[1730/909]` 容器无此问题。
- **修复**：补 `width={1200} height={400}` 或用 aspect 容器模式，一行改动。

### P0-7 hero 资产 immutable 一年缓存与换皮"同名替换"流程直接冲突

- **位置**：`vercel.json:25` ↔ `docs/换皮SOP.md:178-186,236` ↔ `scripts/make-hero-avif.mjs`（头部注释自己写明"换图必须换文件名才能生效"）
- **问题**：`/images/hero-*` 配了 `max-age=31536000, immutable`，而 SOP 的换图流程在原路径重新生成同名文件，且组件硬编码这批文件名，模板结构上做不到改名——换皮上线后，**回访者最长一年仍看到上一款游戏的 hero**。另 `/images/:path*`（1h）与该规则重叠，两条规则至少一条是死配置。SOP 全文无任何缓存/改名提示。
- **修复**：给 hero 路径加版本段（如 `/images/hero-<siteId>-768.avif`，siteId 来自 config 可守护），或降级为可再验证的 max-age；约束写进 SOP。

## 五、审计覆盖外区域（完整性检查结论，供后续跟进）
